**Передача депозитных ставок в кол-центр банка и партнёрский кол-центр**

### ADR-002

### Автор: DevPastet

### Дата: 12.10.2026

### Статус: предложено

---

### Контекст

После запуска маркетинговой кампании ожидается рост звонков. Основные клиенты банка — люди старшего возраста, и многие захотят уточнить условия депозита по телефону. Сейчас операторы не видят ставок ни в одной системе: ставки существуют только в Excel-файлах бэк-офиса.

Предложения сотрудников банка:

1. Дать системе кол-центра банка доступ к текущим ставкам по депозитам.
2. Подключить партнёрский кол-центр и наладить передачу ему актуальных ставок. Партнёр работает во внешней системе, готов принимать ставки только в виде файлов (например, по SFTP) и не может вызывать API банка.
3. Учесть изменения в MVP и опереться на текущий процесс работы со ставками.

Решение продолжает [ADR-001](../Task3/ADR-001-deposit-online-mvp.md). Там ставки перенесены из Excel в модуль АБС, а утверждённые ставки публикуются в топик Kafka `deposit.rates`. Этот ADR добавляет двух новых потребителей того же топика.

### Функциональные требования

| UC-2 | Система кол-центра, Kafka | Обновление ставок в системе кол-центра | Модуль ставок системы кол-центра получает событие и обновляет локальную витрину ставок |

| UC-4 | Сервис выгрузки ставок, SFTP-сервер | Формирование файла для партнёра | Сервис выгрузки ежедневно и при каждом изменении ставок формирует файл с полным актуальным набором ставок, считает контрольную сумму и выкладывает файлы на SFTP-сервер банка |
| UC-5 | Система партнёрского кол-центра, SFTP-сервер | Получение файла партнёром | Система партнёра по расписанию подключается к SFTP-серверу, скачивает последний файл, проверяет контрольную сумму и загружает ставки к себе |
| UC-6 | Оператор партнёрского кол-центра, клиент | Консультация по ставкам у партнёра | Оператор партнёра консультирует клиента по скрипту банка и ставкам из загруженного файла. В файле указан период действия ставок |
| UC-7 | Сервис выгрузки ставок, дежурная смена IT | Контроль доставки | Сервис фиксирует факт выгрузки и факт скачивания файла партнёром. Если файл не сформирован или не скачан в срок, дежурная смена получает оповещение |

### Нефункциональные требования

| № | Требование |
|---|------------|
| NFR-1 | Ставки в системе кол-центра банка обновляются не позднее чем через 5 минут после утверждения в АБС |
| NFR-2 | Файл для партнёра появляется на SFTP-сервере не позднее чем через 15 минут после утверждения ставок и не позднее начала рабочего дня кол-центра |
| NFR-3 | Передача ставок не создаёт дополнительной нагрузки на БД АБС |
| NFR-4 | Партнёру передаются только публичные базовые ставки. Персональные и специальные ставки, персональные данные клиентов не передаются |
| NFR-5 | Обмен с партнёром защищён: протокол SFTP, аутентификация по SSH-ключам, доступ только с адресов партнёра, каталог только на чтение. Внешняя система не получает доступа во внутреннюю сеть банка |
| NFR-6 | Партнёр может проверить целостность и актуальность файла: контрольная сумма SHA-256, номер версии, период действия ставок, время формирования |
| NFR-7 | Недоступность системы кол-центра, сервиса выгрузки или SFTP-сервера не влияет на АБС, интернет-банк и сайт |
| NFR-8 | Доступность консультаций по ставкам 99,9%: при сбое обновления оператор видит последние полученные ставки и время их получения |
| NFR-9 | Используются технологии, уже имеющиеся в банке: Java, Spring Boot, PostgreSQL, React.js, Kafka |
| NFR-10 | Формат файла и схема события задокументированы и версионируются |
| NFR-11 | Все выгрузки и скачивания журналируются. Журнал хранится не менее года |

#### Суть решения

Источник ставок остаётся один — модуль «Ставки по депозитам» в АБС. Процесс работы менеджеров не меняется: они утверждают ставки, остальное происходит автоматически. К топику `deposit.rates` подключаются два новых потребителя.

1. **Модуль ставок в системе кол-центра банка.** Расширение платформы на её штатном стеке. Читает события, хранит ставки в PostgreSQL, показывает их оператору в виджете.
2. **Сервис выгрузки ставок.** Новый небольшой сервис на Java. Читает тот же топик, формирует файл и выкладывает его на SFTP-сервер банка в DMZ. Партнёр сам забирает файл.

Топик `deposit.rates` настроен с уплотнением (log compaction). Ключ сообщения — продукт, срок и валюта. В топике всегда лежит последняя ставка по каждому ключу, поэтому новый потребитель получает полный актуальный набор, прочитав топик с начала. Обращаться к АБС ему не нужно.

#### Компоненты

**АБС** (компоненты из ADR-001, переиспользуются без изменений)

| Компонент | Технологии | Назначение |
|-----------|------------|------------|
| Формы модуля ставок | Delphi | Ввод показателей, расчёт и утверждение ставок |
| Пакет RATES_PKG | Oracle PL/SQL | Расчёт, утверждение, версионирование ставок |
| Таблицы ставок и RATES_OUTBOX | Oracle | Утверждённые ставки и события для публикации |
| OutboxPublisher | Java, Spring Boot | Публикует события из outbox в Kafka. Часть интеграционного адаптера АБС |

**Система кол-центра** (новые компоненты)

| Компонент | Технологии | Назначение |
|-----------|------------|------------|
| RatesEventListener | Java, Spring Kafka | Читает события ставок, обновляет витрину идемпотентно по номеру версии |
| RatesRepository и витрина ставок | Spring Data JPA, PostgreSQL | Локальное хранилище актуальных ставок и времени последнего обновления |
| Rates REST API | Spring Web | Отдаёт ставки и признак их свежести интерфейсу оператора |
| Виджет «Ставки по депозитам» | React.js | Таблица ставок в карточке звонка. Предупреждает, если данные старше суток |

**Сервис выгрузки ставок** (новый контейнер, Java 17, Spring Boot)

| Компонент | Назначение |
|-----------|------------|
| RatesEventListener | Читает топик `deposit.rates` |
| SnapshotBuilder | Держит в памяти актуальный срез ставок, отбрасывает устаревшие версии и ставки с истёкшим сроком |
| ExportScheduler | Запускает выгрузку ежедневно в заданное время и при изменении ставок. Повторяет попытку при сбое |
| FileGenerator | Формирует файлы CSV и XLSX: продукт, срок, валюта, диапазон суммы, ставка, период действия, версия, время формирования |
| FileSigner | Считает SHA-256, формирует файл контрольной суммы |
| SftpPublisher | Выкладывает файлы под временным именем и переименовывает, чтобы партнёр не скачал недописанный файл. Удаляет старые версии |
| ExportAudit | Журналирует выгрузки, проверяет по журналу SFTP-сервера факт скачивания, поднимает оповещение при просрочке |

**SFTP-сервер банка** (новый контейнер, OpenSSH в DMZ). У партнёра отдельная учётная запись, вход по SSH-ключу, доступ только с согласованных адресов, каталог только на чтение. Сервер не имеет доступа во внутреннюю сеть: файлы на него кладёт сервис выгрузки.

#### Формат обмена с партнёром

- Имя файла: `deposit-rates_YYYYMMDD_vNNN.csv`, рядом `deposit-rates_YYYYMMDD_vNNN.xlsx` и `deposit-rates_YYYYMMDD_vNNN.sha256`.
- Дополнительно выкладывается `deposit-rates_latest.csv` — копия последней версии под постоянным именем.
- Каждый файл содержит полный набор ставок, а не изменения. Партнёру достаточно последнего файла.
- CSV предназначен для автоматической загрузки, XLSX — для ручного просмотра, если автоматическая загрузка у партнёра не сработала.

#### Обоснование ключевых решений

| Решение | Почему так |
|---------|------------|
| Оба кол-центра получают ставки из топика `deposit.rates` | Топик уже создаётся в ADR-001. Источник ставок один, расхождения между каналами исключены. АБС не получает новой нагрузки |
| Локальная витрина ставок в системе кол-центра | Оператор видит ставки, даже если Kafka или АБС временно недоступны. Ответ интерфейса быстрый |
| Модуль в системе кол-центра на стеке платформы | Платформа построена на Spring Boot, React.js и PostgreSQL и поддерживает расширения. Разработку могут вести и подрядчик, и Java-специалисты банка |
| Отдельный сервис выгрузки, а не функция адаптера АБС | Сбой выгрузки или SFTP не затрагивает обмен заявками и ставками. Сервис не обращается к Oracle. Его можно менять и выкладывать независимо |
| Партнёр забирает файл сам с SFTP-сервера банка | Банку не нужны учётные данные и сетевой доступ к инфраструктуре партнёра. Факт получения виден в журнале сервера банка. Партнёр сам выбирает расписание |
| Полный срез вместо изменений | Партнёру не нужно накапливать историю. Пропуск одного файла не приводит к ошибке в ставках |
| Только базовые ставки для партнёра | Персональные ставки требуют идентификации клиента и доступа к его данным. Передавать их внешней компании нельзя |

### Альтернативы

| № | Альтернатива | Плюсы | Почему отклонена |
|---|--------------|-------|------------------|
| 1 | Оставить текущий процесс: рассылать Excel-файл со ставками по почте в оба кол-центра | Ничего не нужно разрабатывать | Ручная операция каждый день, ошибки и задержки, нет контроля получения. Оператор ищет ставку в файле во время звонка. Противоречит переносу ставок в АБС |
| 2 | Система кол-центра читает ставки напрямую из БД АБС | Нет промежуточных компонентов, всегда свежие данные | Дополнительная нагрузка на перегруженную базу. Жёсткая связь с внутренней структурой АБС. При недоступности АБС оператор не видит ставок |
| 3 | Система кол-центра синхронно запрашивает ставки по REST у сервиса депозитов | Не нужна собственная витрина и потребитель Kafka | Кол-центр начинает зависеть от доступности депозитного контура интернет-банка. Вариант рабочий и может использоваться как запасной, если подрядчик не сможет подключить платформу к Kafka |
| 4 | Файл для партнёра формирует АБС заданием PL/SQL | Нет нового сервиса | Нагрузка и новая ответственность на АБС. Работа с файлами и SFTP из PL/SQL неудобна и плохо контролируется. Команда АБС и так загружена больше всех |
| 5 | Банк сам отправляет файл на SFTP-сервер партнёра | Партнёру не нужно ничего забирать | Банк хранит учётные данные партнёра и зависит от доступности его сервера. Исходящее соединение из банка во внешнюю сеть. Нет подтверждения, что файл загружен в систему партнёра |
| 6 | Дать операторам партнёра доступ к системе кол-центра банка через VPN или удалённый рабочий стол | Ставки всегда актуальны, файлы не нужны | Внешние сотрудники получают доступ во внутреннюю сеть. Нужны лицензии и рабочие места на 100 человек. Партнёр работает в собственной системе и к этому не готов |
| 7 | REST API для партнёра | Данные по запросу, современный способ | Партнёр прямо заявил, что может принимать только файлы |
| 8 | Операторы партнёра не консультируют по ставкам и переводят звонки в банк | Ставки не передаются наружу | Не снимает нагрузку с кол-центра банка, ради чего партнёр и подключается |

**Недостатки, ограничения, риски**

| № | Недостаток, ограничение или риск | Как снижаем |
|---|-----------------------------------|-------------|
| 1 | Партнёр может консультировать по устаревшим ставкам, если не забрал новый файл | В файле указан период действия. Сервис контролирует факт скачивания и поднимает оповещение. В договоре с партнёром закрепляется расписание загрузки. В скрипте оператора есть оговорка, что окончательную ставку подтверждает банк |
| 2 | Ставки меняются в течение дня, а партнёр забирает файл по расписанию | Файл формируется при каждом изменении. Рекомендуемое расписание партнёра — раз в 15–30 минут. Изменения внутри дня редки: процесс предполагает ежедневное утверждение |
| 3 | Операторы обоих кол-центров видят только базовые ставки и не могут назвать персональную | Оператор банка заводит обращение для расчёта особых условий, как сейчас. Оператор партнёра направляет клиента в интернет-банк, отделение или переводит звонок в банк |
| 4 | Решение зависит от ADR-001: без модуля ставок в АБС и топика `deposit.rates` оно не работает | Публикация ставок запланирована в первой половине MVP. Задачи этого ADR начинаются после неё, порядок отражён в дорожной карте |
| 5 | Доработка системы кол-центра зависит от подрядчика платформы | Используется механизм расширений. Запасной вариант — альтернатива 3. Часть работ могут выполнить Java-специалисты банка |
| 6 | Java-специалисты команды АБС нужны одновременно для адаптера АБС, сервиса выгрузки и, возможно, модуля кол-центра | Сервис выгрузки небольшой и начинается после завершения адаптера. Модуль кол-центра в первую очередь делает подрядчик |
| 7 | Появляется точка обмена с внешней компанией | SFTP-сервер в DMZ без доступа во внутреннюю сеть, SSH-ключи, ограничение по адресам, каталог только на чтение, журналирование. В файле нет персональных данных |
| 8 | Сервис выгрузки хранит срез в памяти и после перезапуска перечитывает топик | Топик уплотнён и мал, чтение занимает секунды. До окончания чтения выгрузка не запускается |
| 9 | Изменение формата файла требует согласования с партнёром | Формат версионируется. Новые поля добавляются в конец. О несовместимых изменениях партнёр предупреждается заранее |
